# Padrões: internacionalização

Os idiomas do projeto são os de `settings.LANGUAGES` — na base, `pt-BR` (padrão) e `en`;
acrescentar um idioma é acrescentar uma linha lá, e o `makemessages` passa a gerar o
catálogo dele em todos os apps. Contexto e motivos
nos ADRs [0004](../adr/0004-catalogo-de-traducao-proprio-por-app.md) e
[0005](../adr/0005-makemessages-idempotente-para-o-ci-verificar-catalogos.md).

## Onde o catálogo mora

**Cada app tem o seu**, em `apps/<app>/locale/`. O `locale/` da raiz — o único em
`LOCALE_PATHS` — guarda só o que não é de app nenhum: `templates/` e `config/`.

Não é preciso rodar nada por app. O Django decide o destino na varredura: ao encontrar um
diretório `locale/`, manda para lá tudo que estiver abaixo do diretório pai.

```bash
python manage.py makemessages       # gera/atualiza os .po
python manage.py compilemessages    # gera os .mo
```

`.po` é versionado; `.mo`, não. Compilar é passo de build — o `Dockerfile` faz no estágio
`assets`, o CI faz antes do pytest.

## Os dois comandos, e por que nenhum precisa de flag aqui

Os dois são versões customizadas (`apps/core/management/commands/`), cada uma cobrindo a
lacuna do comando nativo correspondente:

| | `makemessages` | `compilemessages` |
| --- | --- | --- |
| ignora por padrão (Django) | `CVS`, `.*`, `*~`, `*.pyc` — o `.*` já cobre `.venv` | **nada** |
| ignora por este projeto | `node_modules`, `static/dist`, `tests` | `.venv`, `node_modules` |
| idiomas | `settings.LANGUAGES`, quando não vem `-l/-x/-a` | todos os `.po` que encontrar |

O comando nativo `compilemessages` não ignora nada por padrão: chamado sem `--ignore`, ele
varre a árvore inteira a partir do diretório atual e recompilaria os ~1300 catálogos do
`.venv` e o que viesse de `node_modules`. O override em
`apps/core/management/commands/compilemessages.py` injeta os dois `ignore_patterns` no
`handle()`, do mesmo jeito que o `makemessages.py` já fazia — por isso nenhum dos dois
comandos documentados acima leva flag na linha de comando.

A forma explícita equivalente do `makemessages` — útil se você rodar sem o comando
customizado (o `django-admin` puro, por exemplo, que ainda **exige** a lista de idiomas e
falha sem ela):

```bash
python manage.py makemessages \
    --locale=pt_BR --locale=en \
    --ignore=.venv --ignore=node_modules \
    --no-obsolete --no-location
```

Passar a lista de idiomas à mão também é o caminho quando você quer atualizar **um**
catálogo só: `makemessages -l pt_BR`.

## Como marcar texto

```python
from django.utils.translation import gettext_lazy as _

class Profile(models.Model):
    bio = models.TextField(_("bio"), blank=True)
```

```django
{% load i18n %}
<h1>{% translate "Seu app está no ar" %}</h1>
{% blocktranslate with name=user.name.first %}Olá, {{ name }}{% endblocktranslate %}
```

- `gettext_lazy` em nível de módulo e em atributo de classe (model field, choices, `Meta`);
  `gettext` dentro de função, onde já há request e idioma ativo.
- Não concatene traduções: uma frase inteira por `msgid`, com placeholder nomeado.
- Não traduza chave técnica, nome de evento de log, nem valor de enum persistido.

## O `makemessages` do projeto

`apps/core/management/commands/makemessages.py` sobrescreve o comando para deixá-lo
idempotente:

- **`--no-location`** — sem `arquivo:linha`, que muda a cada refatoração. Para investigar
  uma string: `--add-location=file`.
- **`--no-obsolete`** — mensagem que saiu do código desaparece, em vez de acumular como
  `#~`.
- **sem `POT-Creation-Date`** — o `msgmerge` a reescreve a cada execução; sem removê-la,
  todo `makemessages` sujaria o catálogo de todos os apps sem mudar tradução alguma.
- **sem `-l/-x/-a`**, usa `settings.LANGUAGES`; `node_modules`, `static/dist` e `tests`
  ficam fora da varredura.

Consequência prática: **o CI roda `makemessages` e falha se houver qualquer diff de
`.po`.** String traduzível nova sem catálogo atualizado não passa. Para excluir outros
caminhos, `--ignore=<path>`.

## O `compilemessages` do projeto

`apps/core/management/commands/compilemessages.py` sobrescreve o comando só para acrescentar
o `ignore_patterns` que falta no nativo:

- **`.venv`** — sem isto, todo `.mo` de todo pacote instalado seria recompilado.
- **`node_modules`** — mesmo motivo, para pacote npm que traga catálogo próprio.

Passar `--ignore=<path>` na linha de comando ainda funciona e se soma a estes dois; não os
substitui.

## Precedência (a pegadinha)

Vale a ordem do Django, verificada em `tests/test_i18n.py`:

1. `LOCALE_PATHS` — o `locale/` da raiz — ganha de tudo;
2. entre apps, quem vem **antes** em `INSTALLED_APPS` ganha.

Então `django.contrib.auth` sobrepõe um `msgid` igual em `apps/accounts`. Quando uma
tradução "não pega" e o `.po` está certo, é quase sempre isto. Para cravar um texto, o
lugar é o catálogo da raiz.

## Checklist

- [ ] texto visível marcado com `gettext_lazy`/`translate`
- [ ] `python manage.py makemessages` rodado (e `compilemessages` se você for testar
      a tradução localmente — o `.mo` não é versionado)
- [ ] `.po` do app **e** da raiz revisados e traduzidos (`msgstr` vazio é string sem
      tradução em produção)
- [ ] nenhum `.mo` no commit
